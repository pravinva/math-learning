    Lesson 1 / Method

    Why plan before you code

    Before you write a single line of MATLAB, write down what the program must do, in what order, and where it must decide or repeat. That plan is called an algorithm. Pseudocode and flowcharts are the two standard ways of writing an algorithm down.

    An algorithm is a finite list of precise steps that turns inputs into the required outputs. A cooking recipe is an algorithm for people. A MATLAB script is an algorithm for the computer. Pseudocode and flowcharts sit in between: precise enough that anyone could turn them into code, but free of MATLAB's punctuation rules.

    FormWhat it looks likeBest for
    Structure plan / pseudocodeNumbered or indented lines of structured English: INPUT r, area = pi × r², IF … END IF.Quick to write, easy to translate line by line into MATLAB. Long calculations.
    FlowchartA diagram of standard shapes joined by arrows.Seeing decisions, branches and loops at a glance. Explaining logic to others.
    MATLAB codeThe exact instructions with MATLAB syntax.Running on the computer.

    The Hahn & Valentine textbook used in Practical 3 calls the pseudocode a structure plan. The two names mean the same thing in ENGG100.

    Where planning sits in program design

    Practical 3 lists the seven steps of the program design process. Pseudocode and flowcharts are step 3, and they are what make steps 4 and 5 easy:

    1. Problem statement. Say clearly what has to be solved.
    2. Analysis. Identify the inputs, the outputs and the formulas or rules that connect them.
    3. Design. Write the algorithm as a structure plan (pseudocode) and/or a flowchart.
    4. Implementation. Translate the plan into MATLAB.
    5. Testing. Run cases whose answers you already know, including every branch.
    6. Documentation. Comments, a header, and instructions for the user.
    7. Maintenance. Fix and extend the program later.

    Input, Processing, Output

    Almost every engineering program has the same three stages. Before you plan, fill in an IPO table. Practical 3 calls the middle stage "Operations".

ENGG100 tests and assignments also ask for pseudocode or flowcharts directly, and award marks for them even if your code is not perfect.

    For a program that converts a speed in km/h into m/s, write the IPO table.

    Which step of the program design process are you doing when you choose test values such as 0 and 100?

    Step 5, testing. You choose the test values during design, though, so you know what answers to expect before you run the code.
    Lesson 2 / Method

    Writing good pseudocode

    Pseudocode is structured plain English. There is no single official grammar, but markers expect it to be precise, ordered, and easy to turn into code. A few conventions make that happen.

    The seven rules

    1. One action per line. Each line should become one or two lines of MATLAB.
    2. Write keywords in capitals: INPUT, DISPLAY, IF, ELSE, FOR, WHILE, END. They stand out from your variable names.
    3. Indent everything that sits inside a decision or a loop, exactly as you will in MATLAB.
    4. Close every block: END IF, END FOR, END WHILE. Then nobody has to guess where the block stops.
    5. Use the variable names you will use in the code, with units on the first mention: INPUT d (mm).
    6. No MATLAB punctuation. No semicolons, no fprintf format strings, no '%.2f'. Write DISPLAY stress, not fprintf('%.2f\n', stress);.
    7. Be specific. "Calculate the answer" earns nothing. "area = pi × r²" is a plan.

    Stepwise refinement: Level 1, then Level 2

    For a bigger problem, do not try to write every detail at once. Write a short Level 1 plan of the big steps first. Then refine each step into a Level 2 plan with enough detail to code. This is top-down design, and it is exactly what Practical 3 Q2 asks for.

    Problem: a list of six test marks is given. Report the average, the number of passes (50 or more), and the highest mark.

    Level 1

    1. Input the marks
2. Calculate the average
3. Count the passes
4. Find the highest mark
5. Display the results

    INPUT marks (list of 6)

FOR k = 1 TO n
    total = total + marks(k)

        passes = passes + 1

        best = marks(k)
    END IF
END FOR

DISPLAY average, passes, best

    Notice that Level 2 merged steps 2, 3 and 4 into one loop. Refinement is allowed to rearrange the big steps once you see the detail.

    Lesson 3 / Method

    Flowchart symbols and drawing rules

    A flowchart is the algorithm drawn as standard shapes joined by arrows. The shapes carry meaning, so using the wrong shape is marked as an error, just like a spelling mistake in code.

    The standard symbols

    SymbolNameUse it forMATLAB it becomes
    Terminator (oval)Start and Stop. Exactly one Start; normally one Stop.Top and bottom of the script
    Input/Output (parallelogram)Reading data in, or displaying, printing, plotting results.input, disp, fprintf, plot
    Process (rectangle)A calculation or storing a value. One way in, one way out.x = …;
    Decision (diamond)A yes/no question. One way in, exactly two labelled ways out.if, elseif, the test of a while or for
    Predefined process (rectangle with side bars)Calling a function or sub-program that has its own flowchart.y = myFunction(x);
    Connector (small circle)Joins two parts of a chart that would need a long or crossing arrow, or that continue on another page. Matching letters pair up.Nothing; it is only a drawing aid
    Flowline (arrow)The order of steps. An arrow that points back up is a loop.Line order; end of a loop

    Drawing rules markers check

    1. Start at the top with one Start oval. Flow goes top to bottom, and left to right for side branches.
    2. Every arrow has an arrowhead. A line without direction is ambiguous.
    3. A decision diamond contains a question such as T > 100 ?, never a calculation such as area = pi × r².
    4. Every diamond has exactly two exits, labelled Yes and No (or True and False). For three or more outcomes, chain several diamonds.
    5. Process and input/output boxes have one arrow in and one arrow out.
    6. Every path must reach Stop. Trace each branch with your finger to check.
    7. A loop is an arrow back to a point just before its decision, and something inside the loop must change the tested variable. Otherwise the loop never ends.
    8. Branches rejoin. After an IF, the Yes and No paths meet again before the next step.
    9. Avoid crossing lines. Use connectors if you must.
    10. Keep text short and use the same variable names as the pseudocode and code.

    An example using every symbol

    Read a diameter; if it is positive, call a function that computes the circle area and show it, otherwise report an error.

    Paper or software?

    In tests, draw on paper. Use a pencil, and draw the main column of shapes down the middle first. Put side branches to the right, then add the arrows last. Leave space: crowded flowcharts lose marks for readability. For assignments, diagrams.net (free), PowerPoint or Word shapes, Lucidchart and Visio all have these exact symbols. MATLAB itself does not draw program flowcharts.

    Which symbol do you use for each step? (a) Read the diameter from the keyboard (b) area = pi*r^2 (c) Is the temperature above 100? (d) Plot stress against strain (e) Call the function stressCheck

    (a) parallelogram (input). (b) rectangle (process). (c) diamond (decision). (d) parallelogram (output: a plot is output). (e) predefined process, the rectangle with side bars.

    A student writes x = x + 1 inside a diamond. Why is that wrong, and what should it be?

    A diamond must ask a yes/no question. x = x + 1 is an assignment that changes a value, so it belongs in a process rectangle. If they meant "is x equal to x + 1?", that question is always No and makes no sense.
    Lesson 4 / Control structures

    Sequence: one step after another

    Every algorithm is built from only three structures: sequence, selection (decisions) and repetition (loops). Each has one way in and one way out, so they stack and nest like building blocks. This is called structured programming.

    A sequence runs every step once, in order, with no branches. Most sequence programs follow the IPO pattern: inputs, then calculations, then outputs.

    Worked example: power in a resistor

    Given a voltage V (volts) across a resistor R (ohms), calculate the current I = V / R and the power P = V × I.

    Pseudocode

    INPUT V (V), R (ohm)
I = V / R
P = V × I
DISPLAY I, P

    MATLAB

    V = input('Voltage (V): ');
R = input('Resistance (ohm): ');
I = V / R;        % Ohm's law
P = V * I;        % power in watts
fprintf('I = %.3f A, P = %.2f W\n', I, P)

    Check: V = 12, R = 4 gives I = 3 A, P = 36 W.

    Flowchart

    Order matters

    In a sequence, a value must be calculated before it is used. Swap the two process boxes above and the program uses I before it exists. MATLAB would stop with Unrecognized function or variable 'I'. When you draw a sequence, check each box: is every value on the right-hand side already known?

    Several calculations in one box?

    You may group closely related calculations in one rectangle, one per line, when they form one logical step. Do not hide a decision inside a rectangle, though. If a step involves "if", it needs a diamond.

    Vectors are still one step

    In MATLAB, stress = loads ./ areas processes every rod at once. In a flowchart that is still one process box. You only draw a loop if your code actually uses a loop.

    Put these steps in a correct order: DISPLAY v, v = d / t, INPUT d, t.

    INPUT d, t, then v = d / t, then DISPLAY v. Input, processing, output.
    Lesson 5 / Control structures

    Selection: making decisions

    A decision chooses which steps run. In a flowchart it is a diamond with a Yes exit and a No exit. In pseudocode it is an IF block. In MATLAB it is if, elseif, else or switch. There are five patterns to know.

    On this page, the Yes branch of a decision goes to the right and the No branch continues downwards. Both then rejoin. Some textbooks draw it the other way round; either is fine if the labels are clear.

    Pattern 1: single IF (do something extra, or nothing)

    INPUT speed, limit
IF speed > limit THEN
    DISPLAY "Slow down"
END IF
DISPLAY speed
    if speed > limit
    disp('Slow down')
end
disp(speed)

    The No branch has nothing on it, so the line goes straight down to the join.

    Pattern 2: IF … ELSE (one of two)

    INPUT mark
IF mark >= 50 THEN
    DISPLAY "Pass"
ELSE
    DISPLAY "Fail"
END IF
    if mark >= 50
    disp('Pass')
else
    disp('Fail')
end

    Pattern 3: IF … ELSE IF … ELSE (one of many)

    UOW grade bands: HD 85 or more, D 75 or more, C 65 or more, P 50 or more, otherwise F. The tests are checked from the top, and only the first true branch runs. That is why the order matters: test the highest band first.

    INPUT mark
IF mark >= 85 THEN
    grade = "HD"
ELSE IF mark >= 75 THEN
    grade = "D"
ELSE IF mark >= 65 THEN
    grade = "C"
ELSE IF mark >= 50 THEN
    grade = "P"
ELSE
    grade = "F"
END IF
DISPLAY grade
    if mark >= 85
    grade = 'HD';
elseif mark >= 75
    grade = 'D';
elseif mark >= 65
    grade = 'C';
elseif mark >= 50
    grade = 'P';
else
    grade = 'F';
end
disp(grade)

    Four diamonds for five outcomes. In general, n outcomes need n − 1 diamonds.

    Why the order matters. If you test mark >= 50 first, a mark of 92 is "P", because 92 ≥ 50 is true and the later tests are never reached. When the bands overlap like this, test the strictest condition first.

    Pattern 4: nested IF (a decision inside a branch)

    Use nesting when the second question only makes sense after the first. Here a stress check only matters if a load is applied.

    INPUT load, stress, limit
IF load > 0 THEN
    IF stress > limit THEN
        DISPLAY "FAIL"
    ELSE
        DISPLAY "OK"
    END IF
ELSE
    DISPLAY "No load"
END IF
    if load > 0
    if stress > limit
        disp('FAIL')
    else
        disp('OK')
    end
else
    disp('No load')
end

    Compound conditions: AND, OR, NOT

    One diamond can test a combined condition. In MATLAB, AND is &&, OR is || and NOT is ~. A comfortable room is 18 to 26 °C inclusive, with humidity below 60%:

    INPUT T, H
IF T >= 18 AND T <= 26 AND H < 60 THEN
    DISPLAY "Comfortable"
ELSE
    DISPLAY "Adjust HVAC"
END IF
    if T >= 18 && T <= 26 && H < 60
    disp('Comfortable')
else
    disp('Adjust HVAC')
end

    Write T >= 18 AND T <= 26, never 18 <= T <= 26. MATLAB reads the second form as (18 <= T) <= 26, which is always true.

    Pattern 5: CASE / switch (choose by matching one value)

    When one variable is compared with several exact values, switch is tidier than a chain of elseif. A flowchart has no special switch shape: draw it as a chain of "is it equal to …?" diamonds.

    INPUT mode
CASE mode OF
    1: DISPLAY "Pump off"
    2: DISPLAY "Low speed"
    3: DISPLAY "High speed"
    OTHERWISE: DISPLAY "Invalid mode"
END CASE
    switch mode
    case 1
        disp('Pump off')
    case 2
        disp('Low speed')
    case 3
        disp('High speed')
    otherwise
        disp('Invalid mode')
end

    How many diamonds does a flowchart need to sort a value into 6 categories with an IF / ELSE IF chain?

    5. The last category is whatever is left when every test is No, so it needs no diamond of its own.

    In the comfort example, what does the program display for T = 26, H = 60?

    "Adjust HVAC". T = 26 passes T <= 26, but H < 60 is false when H is exactly 60, and AND needs every part to be true. Boundary values like this are exactly what testers check.
    Lesson 6 / Control structures

    Repetition: loops

    A loop repeats a block of steps. In a flowchart a loop is a decision whose Yes branch runs the body and then an arrow goes back up to the decision. Every loop has three parts: initialise before the loop, test at the diamond, and update inside the body.

    Counted loop: FOR

    Use FOR when you know how many times to repeat before the loop starts. MATLAB's for k = 1:n hides the three parts, but the flowchart shows them: k = 1 (initialise), k <= n ? (test) and k = k + 1 (update).

    Problem: add up 1 + 2 + … + n.

    INPUT n
total = 0
FOR k = 1 TO n
    total = total + k
END FOR
DISPLAY total
    n = input('n: ');
total = 0;              % initialise the accumulator
for k = 1:n
    total = total + k;
end
disp(total)

    Check: n = 100 gives 5050.

    Hexagon notation. Some books draw a FOR loop as one six-sided box containing k = 1 to n. The expanded diamond version above shows exactly what the computer does and is always accepted, so it is the safer choice in a test.

    Condition loop: WHILE

    Use WHILE when you do not know in advance how many repeats are needed: you know the condition to keep going. A water tank starts empty and gains 0.8 m of depth per minute. How many minutes until it is at least 5 m deep?

    level = 0
minutes = 0
WHILE level < 5
    level = level + 0.8
    minutes = minutes + 1
END WHILE
DISPLAY minutes, level
    level = 0;
minutes = 0;
while level < 5
    level = level + 0.8;
    minutes = minutes + 1;
end
fprintf('%d minutes, level %.1f m\n', minutes, level)

    Output: 7 minutes, level 5.6 m. After 6 minutes the level is 4.8, still below 5, so the loop runs once more.

    Infinite loops. If nothing inside the body changes the tested variable, the condition never becomes false and the program never stops. In MATLAB press Ctrl+C to break out. In your flowchart, check that the loop body contains an update.

    Sentinel loop: keep reading until a stop value

    A sentinel is a special value that means "no more data", such as −1 for readings that can never be negative. Read the first value before the loop, and the next value as the last step inside it.

    count = 0
total = 0
INPUT x
WHILE x >= 0
    total = total + x
    count = count + 1
    INPUT x
END WHILE
IF count > 0 THEN
    DISPLAY total / count
ELSE
    DISPLAY "No data"
END IF
    count = 0; total = 0;
x = input('Reading (negative to stop): ');
while x >= 0
    total = total + x;
    count = count + 1;
    x = input('Reading (negative to stop): ');
end
if count > 0
    fprintf('Average = %.2f\n', total / count)
else
    disp('No data')
end

    Choosing the loop

    The question says …Use
    "for each", "every item", "n times", "from 1 to 10"FOR
    "until", "while", "as long as", "how many … before", accuracy or toleranceWHILE
    "keep asking until a valid value", "enter −1 to stop"WHILE with input before the loop and at the end of the body

    Two patterns used everywhere

    Accumulator: start at 0 (or 1 for a product) before the loop, add (or multiply) inside it. Counter: start at 0, add 1 each time something happens. Both must be initialised before the loop. If you set total = 0 inside the loop, it is reset on every pass.

    In the tank example, which line is the initialise step, which is the test, and which is the update?

    Initialise: level = 0 (and minutes = 0). Test: level < 5. Update: level = level + 0.8. The update is what eventually makes the test false.

    How many times does the body of FOR k = 3 TO 12 STEP 3 run, and what values does k take?

    4 times: k = 3, 6, 9, 12. In MATLAB it is for k = 3:3:12.
    Lesson 7 / Combining structures

    Loops with decisions inside

    Most real tasks combine the structures: for each reading, decide something. Because every structure has one way in and one way out, you can place a whole IF block inside a loop body, or a loop inside an IF branch.

    Count the items that meet a condition

    Count how many temperature readings exceed a limit.

    INPUT temps, limit
n = length(temps)
count = 0
FOR k = 1 TO n
    IF temps(k) > limit THEN
        count = count + 1
    END IF
END FOR
DISPLAY count
    temps = [72 85 91 66 88 79];
limit = 80;
n = length(temps);
count = 0;
for k = 1:n
    if temps(k) > limit
        count = count + 1;
    end
end
disp(count)          % 3

    The vectorised MATLAB shortcut is count = sum(temps > limit). Learn the loop first; then you understand what the shortcut does.

    Search: stop when found

    Find the position of the first value equal to a target. The structured way is a WHILE loop with a flag variable found, so that the loop stops as soon as the value is found.

    INPUT v, target
k = 1
found = false
WHILE k <= length(v) AND NOT found
    IF v(k) == target THEN
        found = true
    ELSE
        k = k + 1
    END IF
END WHILE
IF found THEN
    DISPLAY "Found at", k
ELSE
    DISPLAY "Not found"
END IF
    v = [4 9 2 9]; target = 9;
k = 1; found = false;
while k <= length(v) && ~found
    if v(k) == target
        found = true;
    else
        k = k + 1;
    end
end
if found
    fprintf('Found at position %d\n', k)   % 2
else
    disp('Not found')
end

    What about break? MATLAB can also leave a for loop early with break; in pseudocode write EXIT LOOP. In a flowchart, the Yes arrow of the "found?" diamond goes straight to the first box after the loop instead of back to the loop test. Both versions are accepted; the flag version keeps one entry and one exit, which is easier to trace.

    Nested loops

    A loop inside a loop: the inner loop runs completely for every single pass of the outer loop. In the flowchart, the inner loop sits wholly inside the outer loop's body, and its loop-back arrow is inside the outer one. See problems C12 and E5 in the practice sets.

    In the counting example, what goes wrong if count = 0 is moved inside the loop, just before the IF?

    The counter is reset to 0 on every pass, so at the end it can only be 0 or 1, depending only on the last reading. Initialisation belongs before the loop.
    Lesson 8 / Modular design

    Functions and top-down design

    Large programs are split into modules: a main program that calls smaller functions. Each function has its own flowchart. In the main flowchart, a call is drawn as a predefined-process box (a rectangle with side bars).

    How to draw a function

    • The Start oval names the function and its inputs: Start circleArea(d).
    • The Stop oval says what it returns: Return A.
    • Inside, use the usual symbols. A function normally does not use input or display output; it gets values through its inputs and gives results back through its outputs.

    Example: total area of several circular plates

    Main program

    INPUT d (list of diameters)
total = 0
FOR k = 1 TO length(d)
    A = CALL circleArea(d(k))
    DISPLAY k, A
    total = total + A
END FOR
DISPLAY total

    Function

    FUNCTION A = circleArea(d)
    r = d / 2
    A = pi × r²
END FUNCTION
    % main.m
d = [8 10 12];              % mm
total = 0;
for k = 1:length(d)
    A = circleArea(d(k));
    fprintf('Plate %d: %.2f mm^2\n', k, A)
    total = total + A;
end
fprintf('Total: %.2f mm^2\n', total)   % 241.90

% circleArea.m  (its own file, or a local function at the end of the script)
function A = circleArea(d)
r = d / 2;
A = pi * r^2;
end

    Top-down design

    Start from the Level 1 plan. Any step that is big, or used more than once, becomes a function. Then plan each function on its own. This is the same idea as stepwise refinement from Lesson 2, applied to the program's structure.

    Why should circleArea not contain d = input('Diameter: ')?

    The diameter arrives as the input argument, so asking again would ignore the value passed in. It would also stop the main loop from reusing the function for each plate without pausing for the keyboard. Keep input and output in the main program.

    Q3. Vertical motion under gravity (throw.m)

    Analysis. Inputs: g = 9.81 m/s², u = 60 m/s, times t from 0 to 12.3 s in steps of 0.01 s. Operation: s = ut − ½gt² for every t. Output: a labelled plot of s against t.

    INPUT g = 9.81, u = 60
t = 0 to 12.3 in steps of 0.01  (a vector)
s = u·t − ½·g·t²  (for every t, element by element)
DISPLAY plot of s against t, with title, axis labels, grid
    % throw.m  Displacement of a stone thrown upwards
g = 9.81;                 % gravity (m/s^2)
u = 60;                   % launch speed (m/s)
t = 0:0.01:12.3;          % time values (s)
s = u*t - g/2*t.^2;       % .^ squares every element
plot(t, s, 'k', 'LineWidth', 3), grid
title('Vertical motion under gravity')
xlabel('time (s)'), ylabel('vertical displacement (m)')

    There is no loop in the flowchart, because the vector t and the element-wise .^ do every time value in one step. Test: the peak should be at t = u/g ≈ 6.12 s with s = u²/(2g) ≈ 183.5 m, and s should return to 0 at t ≈ 12.23 s.

    Q5. Quadratic equation: every decision box

    Analysis. Inputs: coefficients a, b, c of ax² + bx + c = 0. Outputs: the root(s) or a message. The rules split into cases:

    • a = 0: it is not a quadratic. If b ≠ 0 it is linear, x = −c/b. If b = 0 too, then c = 0 means every x works (indeterminate) and c ≠ 0 means no solution.
    • a ≠ 0: use the discriminant d = b² − 4ac. d < 0 gives complex roots, d = 0 one equal root, d > 0 two real roots.

    Pseudocode

    INPUT a, b, c
IF a == 0 THEN
    IF b == 0 THEN
        IF c == 0 THEN
            DISPLAY "Solution indeterminate"
        ELSE
            DISPLAY "There is no solution"
        END IF
    ELSE
        x = −c / b
        DISPLAY "Linear:", x
    END IF
ELSE
    d = b² − 4ac
    IF d < 0 THEN
        re = −b / (2a)
        im = √(−d) / (2a)
        DISPLAY "Complex roots", re ± im·i
    ELSE IF d == 0 THEN
        x = −b / (2a)
        DISPLAY "Equal roots", x
    ELSE
        x1 = (−b + √d) / (2a)
        x2 = (−b − √d) / (2a)
        DISPLAY x1, x2
    END IF
END IF

    How to trace a flowchart

    1. Write every variable as a column heading. Add a column for the decision and one for output.
    2. Put your finger on Start and follow the arrows.
    3. At a process box, write the new value in its column. Cross out or move down; never overwrite.
    4. At a diamond, write the actual comparison with numbers (16 ≤ 30) and the answer, then follow that arrow.
    5. Stop when you reach Stop. Compare the output with your hand calculation.

    Lesson 12 / Assessment

    Exam and assignment technique

    Questions usually say "Write pseudocode for…", "Draw a flowchart for…", "Convert this flowchart to MATLAB", or "What does this algorithm output?". Each has a reliable method.

    "Write pseudocode / draw a flowchart for…" (about 10 minutes)

    1. Underline every input, output, number and rule word ("each", "if", "until", "otherwise") in the question.
    2. Write the IPO table in the margin: Given, Find, Rules.
    3. Choose structures: "each" means a FOR loop, "if/otherwise" a decision, "until" a WHILE loop.
    4. Write the pseudocode skeleton with the blocks first (FOR … END FOR), then fill in the lines.
    5. Draw the flowchart from the pseudocode, one shape per line, main column first.
    6. Trace one test case through it, and check every path reaches Stop.

    What marks are usually given for

    • Start and Stop present.
    • Correct symbol for each step.
    • Inputs read before they are used; outputs displayed.
    • Correct conditions, including boundaries (≥ versus >).
    • Loops initialised, tested and updated, and returning to the right place.
    • Decision exits labelled; branches rejoin.
    • Neat, readable layout with consistent names.

    "Convert this MATLAB to a flowchart"

    "Convert this flowchart to MATLAB"

    Go shape by shape from Start. When you meet a diamond, ask: does any arrow come back up to this diamond? If yes, it is a loop (while, or for if it has a counter pattern). If no, it is an if. Write the end where the branches rejoin or where the loop arrow leaves.

    "What does this output?"

    Do not guess from the shape of the code. Draw a trace table (Lesson 10) and fill it in row by row. Most errors come from forgetting that the update happens before the test.
