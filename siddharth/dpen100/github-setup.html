Step-by-step on a Windows PC

Step 1 · GitHub account (Gmail)
  1. Open github.com/signup.
  2. Use your Gmail (or “Continue with Google”) to create the account.
  3. Pick a username, set a password, and finish email verification.
Step 2 · Install GitHub Desktop (easiest on Windows)
  1. Download from desktop.github.com → Download for Windows.
  2. Run the installer; open GitHub Desktop.
  3. Click Sign in to GitHub.com and authorise in the browser.
  4. In File → Options → Git, set your name and the same Gmail address, then Save.
Step 3 · Create a folder for MATLAB work
  1. On Windows, create a folder such as Documents\DPEN100-MATLAB.
  2. Inside it, make subfolders if you like: practicals, projects, plots.
  3. Save your .m scripts here when you work in MATLAB (File → Save As… into this folder).
Step 4 · Create the repository and publish it

In GitHub Desktop:

  1. File → New repository…
  2. Name: e.g. dpen100-matlab (no spaces).
  3. Local path: choose Documents (or the parent of your project folder).
  4. Tick Initialize this repository with a README.
  5. Click Create repository.
  6. At the top, click Publish repository (keep it Private if you prefer, then Publish).

You should now see the repo on github.com under your account.

Step 5 · Everyday workflow (after each practical / project session)
  1. Edit / create MATLAB scripts in your local repo folder.
  2. Open GitHub Desktop — changed files appear on the left.
  3. Tick the files to include → type a short summary (e.g. Add proj1_partA plots).
  4. Click Commit to main.
  5. Click Push origin to upload to GitHub.
Optional · Command line on Windows (if you prefer Git Bash)

Install Git for Windows from git-scm.com, then in your project folder:

git init
git add .
git commit -m "Initial MATLAB project"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/dpen100-matlab.git
git push -u origin main

Replace YOUR_USERNAME with Siddharth’s GitHub username. After the first push, later updates are just git add . → git commit -m "…" → git push.

What to put in the repo. MATLAB scripts (.m), exported figures (PNG/PDF), short write-ups, and a README listing which practical/project each file belongs to. Do not upload huge videos, private uni login details, or copyrighted textbook PDFs.

Using GitHub for your MATLAB work (not just pushing)

This is the part that matters day to day: point MATLAB at your repo folder, save scripts and figures there, and let Git track every version so you can go back if something breaks.

A · Make the repo your MATLAB working folder
  1. Open MATLAB.
  2. In the Current Folder panel (top-left address bar), browse to your repo, e.g. Documents\dpen100-matlab.
  3. Everything you create now (scripts, figures) lives inside the repo, so Git can see it. Tip: right-click the folder → Add to Path if you call functions across subfolders.
B · Create and save a script into the repo
  1. Home → New Script (or Ctrl+N).
  2. Write your code, then Save As… into the right subfolder, e.g. projects\proj1_partA.m.
  3. Use clear names that match the task: p03_hello.m, proj1_partB.m. No spaces in file names.
  4. Run with F5 (or the green Run button) and check the plots/output.
C · Save your figures into the repo too

So your plots are versioned alongside the code, export each figure to the plots\ folder. Add these lines at the end of a script:

% after you create figure(1), figure(2), ...
saveas(figure(1), 'plots/proj1_path3d.png');
exportgraphics(figure(2), 'plots/proj1_grade.png', 'Resolution', 150);

Or use the Figure window: File → Save As… and choose the plots folder (PNG or PDF).

D · Add a MATLAB .gitignore (skip junk files)

Create a file named .gitignore in the repo root so Git ignores auto-generated files. In GitHub Desktop you can also do Repository → Repository settings → Ignored files. Paste:

*.asv          % MATLAB autosave backups
*.m~           % editor backups
slprj/         % Simulink build folder
*.mex*         % compiled MEX
octave-workspace
.DS_Store

Keep your .m files and exported .png/.pdf plots — ignore only the temporary stuff above.

E · The MATLAB work cycle (repeat every session)
  1. In MATLAB: write / edit a script, run it, confirm the plot is right.
  2. Export any figures to plots\.
  3. Switch to GitHub Desktop — your changed .m and .png files are listed on the left with a diff.
  4. Write a short Summary describing what you did, e.g. Proj1 Part B: distance & speed plots.
  5. Commit to main, then Push origin.

Commit little and often — one commit per part of a practical/project is ideal. Each commit is a save-point you can return to.

F · MATLAB’s built-in source control (optional, no separate app)

MATLAB can talk to Git directly, so you can commit without leaving MATLAB:

  1. In the Current Folder panel, right-click empty space → Source Control → … (available once the folder is a Git repo).
  2. Right-click a changed file → Add to Git, then Source Control → Commit with a message.
  3. For bigger work, use a MATLAB Project (Home → New → Project → From Git) which wires source control, path, and startup together.

Beginners can ignore this and just use GitHub Desktop — both do the same thing.

G · Go back to an earlier version (why version control helps)
  1. Broke a working script? In GitHub Desktop open the History tab, click an earlier commit to see exactly what changed.
  2. To undo the latest commit’s changes: right-click it → Revert changes in commit (creates a new “undo” commit — safe).
  3. To grab one old file: on github.com open the file → History → view the old version → copy the code back.
H · Use it on another computer (uni lab PC)
  1. Install GitHub Desktop, sign in with the same Gmail account.
  2. File → Clone repository → pick dpen100-matlab → Clone.
  3. Open that folder as MATLAB’s Current Folder and keep working.
  4. Before you start: click Fetch/Pull origin to get your latest work; when done, Commit & Push.
Good README habit. In README.md, keep a short list like: 
# DPEN100 MATLAB
- practicals/p03_hello.m  — Practical 3, F-to-C converter
- projects/proj1_partA.m  — 3D path & grade plots
- plots/proj1_path3d.png  — exported figure for the report
This makes it obvious (to you and your tutor) what each file is for.
