MINE HAUL CYCLE

Open-pit haul truck: kinematics in MATLAB

One repo, one story. A loaded truck climbs a pit ramp, dumps, and returns empty. You analyse the path like GPS ride data, build a piecewise speed profile, then add a conveyor discharge as a projectile. There is no mark scheme. The test is whether the scripts still run in six months.

Not an exam project. Course Projects 1–2 exist if you later want major-assignment flavour. This file is the spine for the 40-day skill block and the six-month keep-warm. Steal MATLAB patterns from Project 1 (path, grade, diff/cumsum) and Project 2 (accel / cruise / brake) — rewrite them for this mine, do not copy-paste unanswered.

The engineering picture

  • Pit floor at elevation 20 m. ROM pad / dump at about 55 m. A two-switchback ramp connects them.
  • Loaded climb: slower, lower peak speed. Empty return: faster. Cycle time = climb + dump wait + return + load wait.
  • Conveyor at the dump: ore leaves the head pulley as a projectile into a bin. Independent \(x\) and \(y\) motion, same as Guide 4.
  • Kinematics only in the first 40 days: position, velocity, acceleration, path length, grade. Forces and rolling resistance wait for the six-month extensions if you want them.

Stage 0 — Repo shape

  3. README.md with one paragraph: what the model is, and “last run” date.
Done when MATLAB’s current folder is the repo, truck_params runs, and you have pushed once.

Stage 1 — Path, grade, distance (rectilinear along a 3-D centreline)

Same analysis as Project 1 Parts A–B, new numbers.

  1. plot3(E,N,z) of the ramp. Label units. Mark loader and dump.
  2. Horizontal grade \(G_i = 100\Delta z_i / \Delta s_{xy,i}\). Elevation and grade vs \(t\) with yyaxis.
  3. 3-D segment lengths, cumulative \(s\) (m and km), segment speeds in km/h.
  4. fprintf total length, mean climb speed, steepest grade.
Scripts s1_path3d.m, s1_grade.m, s1_distance_speed.m + saved figures.

Stage 2 — Piecewise speed law (you drive the kinematics)

GPS times are one possible climb. Now prescribe motion: accelerate to \(v_{\mathrm{loaded,max}}\), cruise, brake to rest at the dump. Use SUVAT on each piece, then stack arrays.

  1. From Stage 1, take path length \(S\) as the 1-D coordinate \(s\).
  2. Compute \(t_{\mathrm{acc}}\), \(s_{\mathrm{acc}}\), \(t_{\mathrm{brake}}\), \(s_{\mathrm{brake}}\), cruise length. If \(S\) is too short for cruise, cut the peak speed (an if).
  3. Build \(t\), \(s(t)\), \(v(t)\), \(a(t)\) with linspace on each piece and concatenate.
  4. Plot \(s,v,a\) vs \(t\) in one subplot figure. Print cycle climb time.
Function piecewise_motion.m \((S, v_{\max}, a_{\mathrm{acc}}, a_{\mathrm{brake}})\) returning \(t,s,v,a\). Script s2_loaded_climb.m calls it.

Stage 3 — Empty return and a full cycle

  1. Return along the same path, \(v_{\mathrm{empty,max}}\), same accel/brake magnitudes.
  2. Insert constant-position waits \(t_{\mathrm{dump}}\) and \(t_{\mathrm{load}}\) (velocity zero).
  3. One figure: speed vs time for the whole cycle, shaded waits.
  4. Productivity: \(T_{\mathrm{cycle}}\) and \(\mathrm{tph} = 3600 \times \mathrm{payload}/T_{\mathrm{cycle}}\).
s3_full_cycle.m + cycle_time.m + one cycle figure.

Stage 4 — Conveyor discharge (curvilinear projectile)

Ore leaves a conveyor at \(v_0 = 3.5\,\mathrm{m/s}\), belt angle \(18^\circ\), lip 4.0 m above the bin floor, \(g=9.81\). Ignore air resistance.

  1. Vectorised \(x(t)=(v_0\cos\theta)t\), \(y(t)=h+(v_0\sin\theta)t-\tfrac12 gt^2\), land when \(y=0\).
  2. Plot trajectory; mark lip and landing. Print time of flight and range.
  3. Optional: a second belt speed. Overlay both trajectories.
projectile_xy.m + s4_conveyor.m. This is Guide 4 coded, not re-derived on paper for its own sake.

Stage 5 — File I/O and a short memo

  1. Write data/ramp_climb.csv and read it with readmatrix (or csvread).
  2. Save every figure under figures/ with saveas.
  3. A one-page memo.md: what the cycle time is, where the steepest grade is, where the projectile lands, and one thing you would measure on a real ramp next.
The repo runs from a single run_all.m that calls stages 1–4 in order.

Six-month extensions (one feature per month, not a rewrite)

  1. Loaded vs empty comparison plot on the same axes; print \(\Delta T_{\mathrm{cycle}}\).
  2. Second ramp (gentler grade, longer path). Same functions, new CSV. Which ramp wins on tph?
  3. Shovel toss / waste dump as a second projectile (different \(v_0,\theta,h\)).
  4. Shift file: repeat the cycle 20 times with a random extra wait 0–15 s at the dump (rand). Histogram of tph.
  5. Animation: truck marker moving along \(E(s),N(s)\) with drawnow or comet3.
  6. Freeze: run run_all.m on a clean MATLAB session. If it fails, that month’s job is to make it run, not to add features.
